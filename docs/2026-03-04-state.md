## What's Being Tested

### Vapi webhook delivery (the big one)

Outbound calls work -- Vapi places the call, the voice agent has a conversation, the call completes. But the `end-of-call-report` webhook that delivers the transcript back to our server has been unreliable.

**Fix applied**: Cloudflare Page Rule on `api.holdplz.ai/vapi/*` that disables Browser Integrity Check and sets Security Level to Essentially Off. This lets Vapi's server-to-server POSTs through without being challenged.

**Status**: Fix deployed, awaiting confirmation on next test call.

**Fallback added (just shipped)**: Even if the webhook never arrives, calls no longer get stuck forever:
- `status-update` events (which DO arrive) now mark calls as `failed_ended` or `failed_failed`
- Background job marks any `in_progress` call older than 15 min as `failed_timeout`
- `check_duplicate_call()` ignores stale calls, so users can retry

### Full circuit

The end-to-end flow: text request -> payment -> call -> webhook -> SMS result. Payment flow is fixed. Blocked on reliable webhook delivery for the last mile.

## How Reality Differs from the Docs

### Pricing

**Docs say**: $19.99/month (product doc, production setup guide, claudio roadmap)
**Actual**: $9.99/month subscription OR $1/request via Payment Links. Dual-plan model with a free tier that gates call-intent behind a paywall.

### Subscription states

**Docs say**: `trial` -> `active` -> `past_due` -> `canceled` (+ `allowlisted` override)
**Actual**: `pending_consent` -> `active` | `free` | `inactive` | `canceled`. The `pending_consent` state is central -- users must explicitly consent via SMS before activation. Free tier exists with call-intent paywall. `allowlisted` flag bypasses payment gates for testers.

### LLM strategy

**Docs say**: Claude Sonnet 4.5 for everything
**Actual**: Tiered model fallback via `app/services/llm.py`:
- `tier="standard"`: Haiku -> Sonnet (for cheap calls: judge, welcome messages, categorization)
- `tier="premium"`: Sonnet -> Haiku (for orchestrator, call summarization)
- Returns `None` if all models fail -- callers handle with static fallbacks

This module didn't exist in the original design. All LLM calls now route through it.

### Sessions/requests data model

**Docs say**: Nothing (not in any original doc)
**Actual**: An LLM judge (`app/services/judge.py`) classifies every message exchange into sessions and requests. Sessions group related messages. Requests have types (info_query, reservation, appointment, etc.) and resolution states. This powers the admin dashboard's conversation view and will eventually drive analytics.

### Payment gating

**Docs say**: Simple subscription check at SMS gateway level
**Actual**: Call-intent paywall. Free users get full access to search/lookup tools. The paywall fires only when Claude tries to use `call_business` or `pre_call_check` -- the moment of highest conversion intent. Payment Links (not saved cards) are the primary payment method, which required a custom matching chain in `billing.py`: metadata -> client_reference_id -> email match -> recent payment-link SMS match.

### Vapi webhook URL

**Docs say** (changelog.md): Railway direct domain bypasses Cloudflare
**Actual** (decisions.md, which is correct): Railway direct domain does NOT work. The fix is a Cloudflare Page Rule that disables bot protection on `/vapi/*`. The `VAPI_SERVER_URL` env var points to `https://api.holdplz.ai/vapi/events` and goes through Cloudflare.

### Call failure handling

**Docs say**: Retry system with exponential backoff
**Actual**: All of that, plus:
- `failure_log` table for typed, severity-rated error tracking (visible in admin dashboard)
- `cleanup_stale_calls()` background job marks abandoned `in_progress` calls as `failed_timeout`
- `_ensure_call_status_updated()` catches terminal status-update events even when end-of-call-report never arrives
- `check_duplicate_call()` has a 15-minute age filter so stale calls don't block new attempts

### Business intelligence

**Docs say** (product doc): Phone scoring, fact caching
**Actual**: All of that, plus:
- `business_profiles` table -- aggregate dossier per business (total calls, success rate, known contacts, avg hold time, busy patterns)
- `extract_call_intelligence()` -- background LLM task that parses transcripts for contacts, IVR structure, hold times
- `ensure_business_profile()` + `increment_business_calls()` run on every call completion

### Message logging

**Docs say**: `message_log` captures all inbound/outbound SMS
**Actual** (before today's fix): Only the orchestrator response path logged outbound messages. ~30 other SMS paths (consent, billing, welcome, call failures, retries, proactive) called `send_sms()` directly without logging.
**Actual** (after today's fix): `send_sms()` now logs every outbound message to `message_log`. All paths covered.

### Voice inbound

**Docs say** (product doc): Twilio forwards to Vapi SIP endpoint, voice agent has full tool access
**Actual**: Implemented but simpler. Twilio voice webhook returns TwiML that connects to Vapi. The Vapi assistant-request webhook does auth and injects user memory. No tool calling during inbound voice calls yet -- the agent can answer questions from memory but can't trigger outbound calls mid-conversation.

### Proactive intelligence

**Docs say**: Deterministic trigger computation (no LLM), fires at 8am daily
**Actual**: Implemented. Runs every hour (checks are idempotent, 8am logic is inside). Includes free-tier re-engagement nudges. No evidence yet of how well the pattern matching works -- needs real usage data.

## Architecture as Built

```
User's Phone
    |
    +-- SMS --> Twilio --> POST /sms/webhook
    |                          |
    +-- Call -> Twilio --> POST /voice/webhook --> Vapi (inbound)
                               |
                     +---------+---------+
                     |  FastAPI Server   |  Railway + Cloudflare
                     |  Python 3.12     |
                     |                   |
                     |  Orchestrator     |--> Claude API (Haiku/Sonnet fallback)
                     |  Resolution      |--> Google Places API v2
                     |  Ladder          |--> Tavily Web Search
                     |                   |--> Vapi Outbound Calls
                     |  LLM Judge       |
                     |  Business Intel  |
                     |                   |
                     |  SQLite + Files   |
                     +--------+----------+
                              |
                    +---------+---------+
                    |  Vapi.ai          |
                    |  Voice Agent      |--> 11Labs TTS
                    |  (outbound)       |--> Deepgram STT
                    |                   |--> Claude LLM
                    +-------------------+
                              |
                    POST /vapi/events
                    (end-of-call-report, status-update)
                              |
                    Cloudflare Page Rule:
                    api.holdplz.ai/vapi/* = security off

Background tasks (every 5 min):
  - cleanup_stale_calls() -- mark abandoned calls as failed_timeout
  - process_retries() -- re-initiate failed calls with retry_pending status
  - process_queued_calls() -- fire calls queued for business opening

Background tasks (every 1 hour):
  - run_proactive_checks() -- trigger-based outreach (8am gate inside)
```
